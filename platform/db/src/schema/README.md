# Shared reference tables — why these carry no `tenant_id`

Every table in `public` is one of two kinds, and the live catalogue decides which (see
`platform/db/src/roles-and-rls.integration.test.ts`, "derived from `pg_class`", and
`ledger/src/rls-cross-tenant-isolation.integration.test.ts`, "coverage"):

- a table **with** `tenant_id NOT NULL` must have row-level security `ENABLE`d **and** `FORCE`d;
- a table **without** `tenant_id` must have neither.

Both directions are asserted against a real Postgres on every run, so a new table is checked the
moment it exists. The static `tenant-column-gate` that used to scan the migration SQL for the same
rule was retired by ADR-0016: a green run of it proved nothing for a one-lined or
`IF NOT EXISTS` table, and the two suites above are the coverage that actually bit. What the
gate owned that the suites do not is the **prose** below — the
per-table reason a shared table is shared. It lives here now.

| Table                       | Why it is shared, not tenant-owned                                                                                                                                                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `tenant`                    | The tenant root. Its own `id` _is_ the tenant identifier every other table's `tenant_id` references.                                                                                                                                                                                                                                                                           |
| `currency`                  | ISO 4217 list (NFR-13).                                                                                                                                                                                                                                                                                                                                                        |
| `instrument`                | The shared instrument catalogue — an explicit FR-45 exclusion. `owner_tenant_id` (nullable, all-NULL today) is a deliberately distinct column, not a substitute for `tenant_id`.                                                                                                                                                                                               |
| `instrument_provider_map`   | Attributes of the shared catalogue, one row per instrument/provider pair (FR-5, AC3, AC16).                                                                                                                                                                                                                                                                                    |
| `fx_rate_daily`             | Shared FX observation series (FR-45's exclusion).                                                                                                                                                                                                                                                                                                                              |
| `fx_tracked_pair`           | The FX pairs the daily pull covers on top of the ones holdings imply. The rates land in a global series every tenant's valuation reads, and the ingestion worker that consumes the list runs cross-tenant with no session context to filter on — a `tenant_id` here would be a column no reader may filter by and no writer could honestly populate. See `fx-tracked-pair.ts`. |
| `instrument_price_daily`    | Shared price series (FR-45's exclusion).                                                                                                                                                                                                                                                                                                                                       |
| `instrument_quote_latest`   | Shared latest-quote cache, one row per instrument.                                                                                                                                                                                                                                                                                                                             |
| `provider_fetch_log`        | Operational log of provider fetch calls, not tenant data.                                                                                                                                                                                                                                                                                                                      |
| `instrument_backfill_state` | Backfill progress is a property of the shared catalogue, not of any tenant.                                                                                                                                                                                                                                                                                                    |
| `instrument_price_gap`      | Provider-confirmed empty business days per catalogue instrument, the weekly gap-repair scan's memory. Same reasoning as `instrument_backfill_state`.                                                                                                                                                                                                                           |
| `market_calendar`           | Shared trading-calendar reference data.                                                                                                                                                                                                                                                                                                                                        |
| `market_data_epoch`         | The single-row market-data epoch counter (SH-1): a property of the shared price/FX series whose writes bump it, read by every tenant's valuation path. See `market-data-epoch.ts`.                                                                                                                                                                                             |
| `login_attempt`             | Login rate-limiting: every attempt is keyed by submitted email and caller IP and tracked _before_ any tenant is known — an attempt against an email that resolves to no user still has to be tracked. See `login-attempt.ts`.                                                                                                                                                  |
| `ops_indicator`             | The worker's alerting sweep writes it and the unauthenticated `GET /health` reads it (SH-34): operational data about the deployment, one row per condition, so a `tenant_id` would be a column no reader is allowed to filter on. See `ops-indicator.ts`.                                                                                                                      |
| `__drizzle_migrations`      | Drizzle's own journal, created at runtime in the `drizzle` schema.                                                                                                                                                                                                                                                                                                             |

Adding a shared table means adding a row here in the same change, next to the schema file's own doc
comment. Adding a tenant table means `tenant_id NOT NULL` + `ENABLE` + `FORCE` in its migration and
an entry in `TENANT_SCOPED_TABLES` in the cross-tenant isolation suite — which fails naming the table
until you do.
